# Self Heal — 自我修复

当任何操作失败时，不要简单地报告失败。自动执行以下诊断和修复流程。

## 自我修复循环

```
操作失败
  ↓
[1] 分类错误类型
  ↓
[2] 诊断根因
  ↓
[3] 尝试替代方案（最多3次）
  ↓
[4] 全部失败 → 精确汇报 + 写入 memory
```

## 第一步：错误分类

| 错误类型 | 典型信号 | 策略 |
|----------|----------|------|
| 权限不足 | "Access denied", "Permission", "Elevation" | 提示用户需要管理员权限 |
| 路径不存在 | "not found", "does not exist", "cannot find" | 检查路径，自动创建目录 |
| 网络问题 | "timeout", "unreachable", "connection refused" | 重试3次（间隔递增），检查网络 |
| 格式/语法错误 | "invalid", "unexpected token", "parse error" | 修正格式，查看上下文 |
| 资源不足 | "out of memory", "disk full", "quota exceeded" | 检查资源，清理空间 |
| 依赖缺失 | "module not found", "command not recognized" | 自动安装缺失依赖 |
| 锁定/占用 | "being used by another process", "locked" | 等待后重试，或建议关闭占用程序 |

## 第二步：诊断

在尝试修复前，先收集诊断信息：
- 执行的完整命令是什么
- 错误信息全文
- 当前工作目录
- 相关文件是否存在
- 相关进程是否在运行

## 第三步：尝试替代方案

```
尝试1：用不同参数重试（如换路径、换编码）
  ↓ 失败
尝试2：用不同方法实现同样目标（如 PowerShell → Python）
  ↓ 失败
尝试3：降级方案（如整体下载 → 分片下载）
  ↓ 失败
进入第四步
```

## 第四步：精确汇报 + 记忆

汇报格式：
```
❌ 操作失败：[简述]
📋 根因：[诊断结果]
🔄 已尝试：
  1. [方案1] → [为什么失败]
  2. [方案2] → [为什么失败]
  3. [方案3] → [为什么失败]
💡 建议：[需要用户做什么，或什么条件下可以重试]
```

同时将失败经验写入 `memory/YYYY-MM-DD.md`，格式：
```markdown
## 踩坑记录：{简述}
- 时间：{timestamp}
- 根因：{root cause}
- 可行方案：{what works}
- 不可行方案：{what doesn't work}
```

## 何时放弃

以下情况不要反复重试，直接汇报：
- 需要用户输入/确认（如密码、权限）
- 外部服务明确拒绝（如 API 返回 403/401）
- 数据不可恢复的破坏性操作
- 已经尝试了3种不同方案
